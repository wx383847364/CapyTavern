## 4. 状态怎么推

`dispatchKey` 可写在里程碑或子项上，按「`dispatch.md` 主表第一列以它开头」匹配。子项的状态取下面第一条命中的：

1. 子项自己的 `dispatchKey` 命中：「阻塞」→ `BLOCKED`，「已验收」→ `PASS`，「待验收」→ `REVIEW`，「进行中」→ `IMPLEMENTING`，「已派出」→ `DISPATCHED`。
2. 所属里程碑的 `dispatchKey` 为「已验收」→ `PASS`；为「阻塞」→ `BLOCKED`。
3. `evidence` 非空且文件全部存在 → `REVIEW`（有产物、没验收）。
4. 都没有 → `OPEN`。`evidence` 为空不算存在。

里程碑状态：子项全 `PASS` 才算 `PASS`；有 `BLOCKED` 就是 `BLOCKED`；有一项不是 `OPEN` 就是 `IMPLEMENTING`；否则 `OPEN`。
进度百分比：`PASS` 子项数 ÷ 子项总数，四舍五入到整数；`REVIEW` 不算完成，单独显示「待验收 n 项」。
NEXT：依赖全部 `PASS`、自己未 `PASS` 的非并行里程碑里排最前的一个；里程碑内先取第一个 `REVIEW` 的子项（待验收的先验，不往后做），没有再取第一个 `OPEN` / `DISPATCHED` / `IMPLEMENTING` / `BLOCKED` 的子项。（2026-11-06 改：原先是 `REVIEW` 排最后，导致页面指向还没开的 P3b。）图上用紫色光环。

页面只能显示推出来的结果。推不出来的写 `UNKNOWN`，不猜。

## 5. 五页

### 01 项目总览

- 顶部：当前里程碑名、整体进度环（全部子项）、本里程碑进度。
- 五张数字卡：里程碑完成数 / 总数、待验收、阻塞、持锁中、未提交文件。
- NEXT 卡：下一步做什么、谁做、做完解锁什么。
- 最近证据：`dispatch.md` 证据列最近五条。

### 02 里程碑导航图（本次重点）

- 横向一条 P0 → P1 → P2 → P3 → P4 主链，P5 Spine 作为并行支线挂在 P1 旁，标「不挡玩法」。
- 每个里程碑是一张卡：编号、名称、状态色、进度条、负责人。展开后显示子项小节点。
- 依赖用箭头，未满足的依赖画虚线。
- 点子项开抽屉：目标、验收要点、证据路径、对应任务单、当前持锁人。

### 03 项目架构图

- 按 `分层与热更边界.md` 四层画泳道：表现、输入、玩法、数据与存档。
- `client/` 扫出来的脚本和场景按登记表的路径前缀归层；归不进去的放「未归层」。
- 依赖边从脚本 / 场景引用推出。表现层指向玩法层的边标红（违反「表现只订阅」）。
- 目录还没建的层显示空泳道和「未开工」，不隐藏。

### 04 功能导流图

玩家流程：新档 → 酒馆 → 招募 → 整备 → 出征 → 加载 → 战斗 → 胜利领奖 / 失败 → 回酒馆。
每个节点在登记表里挂到负责它的里程碑子项，颜色跟子项状态走。玩家现在能走到哪一步，一眼看出来。

### 05 进度与风险

- 交付链：每个里程碑一条泳道，子项按顺序排成小方块。
- 任务单表：直接显示 `dispatch.md` 主表。
- 阻塞与风险：`dispatch.md` 阻塞段 + 迭代索引「最新阻塞」。
- 写锁：持锁中的行，超过 2 小时标黄。
- 未提交：按岗分组的文件数。
- 数据来源：每个来源的路径和读取时间。

## 6. 接口

- `GET /api/snapshot`：上次扫描结果。
- `POST /api/scans`：重新读一遍，返回新快照和与上次的差异。
- `GET /api/scans/history`：最近 20 次扫描摘要。

不提供任意路径读取、任意命令执行和状态编辑。
