## 1. 两份稿子怎么裁

v0.6 写明自己替换了七天计划里的「酒馆静态界面」。下面三刀策划已于 2026-11-04 确认。领奖细则在 P2，拥有清单是第 6 节的 `ownedItems`。两份稿的引擎抬头已于 2026-11-05 改完，P0 可以建 `client/`。

| 题目 | 程序按这个做 | 不再按这个做 |
|---|---|---|
| 酒馆 | 固定镜头的俯视 2D 单屏。场景里远征队伍只显示队长，点地行走，三个交互点加上界面入口 | 七天计划里的整页静态酒馆 |
| 队伍 | 四个槽位，1～4 人可出征。战斗快捷键 1～4 对应槽位，队长单独记 | 必须满四人才能出征；1～4 固定对应战士、盗贼、法师、牧师 |
| 战斗内容 | 仍用七天计划：四名固定职业、每人 4 个主动技能、八槽装备、每职业二选一天赋、一场 4 个敌人。领奖见 P2 | 不把经营、探索、天赋树、四件套拉进第一刀 |

Spine 进资源管线。战斗灰盒用色块占位，第一场可玩不挡在骨骼动画上。表现随后按同一套状态名换 Spine。

不沿用七天计划的 42 小时排期。那个排期假设一人开发、静态酒馆、不做骨骼。

## 2. 第一刀要玩到的循环

新档进酒馆 → 招募 1～4 名固定职业 → 查看八槽和天赋 → 选择关卡出征 → 战斗里点选角色、左键移动、右键目标、Q/W/E/R 放当前角色的技能 → 胜利后从已招募职业里领一件还没有的肩膀或鞋子，或失败回酒馆 → 只显示队长，换装或换天赋后再出征。重启保留队伍、槽位、队长、已拥有物品、穿戴、天赋和领奖状态，酒馆坐标回到默认落点。

## 3. 程序不做

- 酒馆经营、随机招募、等级、天赋树、装备强化、随机词条、四件套。
- 框选、多选、全队移动、WASD、手柄、触控。
- 战中复活、战斗中途存档。退出战斗视为未完成，下次从酒馆重试。
- 真服务端、账号、热更新。服务器岗本切片不建 `server/`、`protocol/`。
- 把概念图整张铺成可点界面。按钮、文字、血条分开做。

## 5. 场景状态

同一时刻只有一个玩法上下文：`Tavern`、`Battle`、`Modal`、`Loading`。

输入先交给最上层界面。界面没接住的点击，才按当前上下文变成移动、交互、选人或技能。一次点击只做一件事。切场景时清掉未完成的移动、待交互和技能请求。

酒馆开着功能面板时队长站着，不走、不点场景。Esc 一次只关一层。出征加载开始之后，Esc 不取消这次加载。

战斗暂停时不执行新的移动、目标和施法。失去焦点时：酒馆停步并取消待交互；战斗暂停，回来后等玩家继续。

## 6. 数据契约

这些字段是存档和以后协议的同一套名字。本切片只写本地单档。

| 字段 | 含义 | 谁改 |
|---|---|---|
| `slots[4]` | 成员身份和顺序。空槽合法。战斗快捷键和头像都读它 | 酒馆招募、调整顺序 |
| `captainSlot` | 队长。必须指向当前队伍里的一名成员；空队伍为空 | 只在酒馆改 |
| `inspectSlot` | 整备面板正在看谁 | 只影响面板，不改队长，不进战斗 |
| `selectedSlot` | 战斗里谁在接命令 | 只在战斗里改，不写回队长 |
| `ownedItems` | 已拥有的物品 id，含已经穿上的。领奖和「尚未拥有」只查这张表 | 招募写入初始装备；领取奖励时追加 |
| `equips` | 每名成员八槽正在穿的：武器、头盔、胸甲、肩膀、裤子、鞋子、戒指、护符；槽位 id 固定为 `weapon, helmet, chest, shoulder, legs, boots, ring, amulet`（与 `items.json` 的 `slot` 一致）。每件都必须在 `ownedItems` 里 | 酒馆点击更换 |
| `talentId` | 每名成员一个已选天赋。两个选项互斥 | 酒馆可改，战斗中锁定 |
| `pendingReward` | 上一场胜利还没领完。非空时不能再出征。领完后清空 | 结算写入；领取时把选中物品写入 `ownedItems` |
| `claimedRuns` | 已经领过奖的场次 | 防止重复发奖 |

`ownedItems` 单独存，不用 `equips` 加 `pendingReward` 反推。换下来的装备仍算拥有（操作稿：替换不销毁原装备）。只看身上穿的，会把这件再发一次。

不进存档：酒馆坐标、战斗中的生命、资源、冷却、仇恨、选中和临时增益。下次出征按开场规则回满并清空冷却。

招募时，这名成员的八件初始装备同时写入 `ownedItems` 和 `equips`，同一次提交。失败则两边都回到写入前。换装比较是预览，点「装备」才改 `equips`，不改拥有清单。领到的奖励只进 `ownedItems`，不自动穿上。

第一场内容仍用七天计划的数量：4 个固定职业、16 个主动技能、32 件初始装备、8 件肩膀或鞋子替换件、8 个天赋、3 类敌人、1 个关卡。技能效果走同一个结算入口，职业差异放在配置里。

### P1 战斗灰盒

- 先 1 名、再 1～4 名角色出现在无障碍单屏。空槽不生成。
- 左键点己方或头像、按槽位键选人。左键点地移动。右键点敌人攻击。牧师右键点队友治疗。Q/W/E/R 放当前角色的四个技能。
- 切换选人不打断别人已经在执行的命令，也不重置别人的冷却。
- 无效技能不扣资源、不进冷却。按住技能键不连发。
- 敌人：2 个近战、1 个施法者、1 个精英。全灭胜利；出战成员全倒下或 120 秒失败。倒下的人不能再下令，没有战内复活。
- 验收：用 1 人和 4 人各打完一场。空槽的数字键不改变当前选择。

4. **契约变更**：战斗事件见下表，2026-11-06 制作人定稿。信号参数全是纯数据，不带节点引用；结算按固定步长在逻辑层推进，不读动画回调；表现只订阅。无存档字段变更。

| 信号 | 参数 | 说明 |
|---|---|---|
| `battle_started` | `seed, allies, enemies` | 战斗随机种子写日志，暴击等随机只走这个种子，测试可复现 |
| `unit_spawned` | `unit_id, side, slot, class_id, max_hp, pos` | `side` 取 `ally`/`enemy`，敌人 `slot=-1`，空槽不发 |
| `command_issued` | `unit_id, kind, target_id, pos` | `kind` 取 `move`/`attack`/`heal`/`skill` |
| `command_rejected` | `unit_id, kind, reason` | `reason` 取 `no_target`/`out_of_range`/`cooldown`/`gcd`/`no_resource`/`unit_down`/`paused`；被拒不扣资源、不进冷却 |
| `skill_cast` | `unit_id, skill_id, target_id, cost, cd_until` | `cd_until` 是战斗时间秒 |
| `damage_dealt` | `source_id, target_id, amount, skill_id, is_crit, hp_after` | `skill_id` 为空表示普攻 |
| `heal_done` | `source_id, target_id, amount, effective, skill_id, hp_after` | `effective` 是实际补上的量 |
| `resource_changed` | `unit_id, kind, value, max` | `kind` 取 `rage`/`energy`/`mana`，只在变化时发 |
| `status_applied` / `status_expired` | `unit_id, status_id, source_id, until` | 减伤、嘲讽、攻速提升等；`until` 战斗时间秒 |
| `enemy_cast_started` / `enemy_cast_interrupted` | `unit_id, skill_id, ends_at` / `unit_id, by_id` | 施法者敌人读条与被打断 |
| `unit_downed` | `unit_id, by_id` | 倒下的人不能再下令 |
| `battle_ended` | `result, reason, elapsed` | `result` 取 `win`/`lose`；`reason` 取 `all_enemies_down`/`all_allies_down`/`timeout` |
| `selection_changed` | `slot` | 只给界面用，不进结算日志 |

日志：除 `selection_changed` 外，每个事件一行 JSON，写 `user://battle_log.jsonl`，同时打到标准输出。改信号名或参数要先报制作人。

### P2 配置和单档

- 四职业、八槽、二选一天赋、两件套（肩膀 + 鞋子）读配置生效。
- 招募一次写入成员和八件初始装备（同时进 `ownedItems` 和 `equips`），重复招募不复制。
- 胜利领奖按七天稿第 2 节第 6、7 条：先从已招募的全部职业里选一个，本场没上场的也可以领；再从该职业还没在 `ownedItems` 里的肩膀或鞋子中选 1 件。两件都没有就由玩家选，只剩 1 件就直接领。该职业两件都有则引导换职业。8 件替换件都已拥有时显示收集完成，不发重复件。奖励写入 `ownedItems`，不自动穿上。失败不发装备。同一场不能领两次。
