# 远征酒馆 游戏操作功能设计

版本：0.6 草案  
日期：2026-11-01  
适用项目：Godot 4 客户端（2D，角色用 Spine）  
目标平台：PC 键盘与鼠标

玩家在酒馆中通过队长代表整支远征队伍，在战斗场景中分别指挥本次出征的全部队员。操作设计分为酒馆场景和战斗场景两部分，共用同一份队伍、装备和天赋数据。

**已确定的基础规则：**

- 个人远征队伍最多四人，至少一人即可出征；队伍非空时包含且仅包含一名队长，不要求补满人员。
- 酒馆是游戏场景；远征队伍在酒馆场景中只展示队长的角色形象。
- 战斗场景中本次出征的全部成员出现，每一名都可以被选择并接受玩家操作；一人出征就只生成一人，满员时生成四人。

下文注明“建议”的内容是本稿补充的操作方案；既有战斗输入另行注明。新增场景与队长规则属于开发目标，不代表当前原型已经实现。

| 概念 | 定义 |
| --- | --- |
| 队长 | 当前已入队成员中的一人，承担酒馆中的队伍形象展示职责 |
| 队伍槽位 | 四个成员位置，用于对应头像和战斗选人快捷键；与队长身份分别记录 |
| 当前操作角色 | 战斗中当前被选中的队员，接收移动、目标和技能指令 |
| 整备查看对象 | 酒馆角色面板中正在查看的队员；查看对象可以与队长不同 |

## 1 酒馆场景操作

### 1.1 场景与角色展示

酒馆是玩家组队、整备与出征的活动场景。远征队伍只有队长出现在场景中，其他已入队成员通过队伍栏和面板管理。队长身份、面板查看对象和战斗操作对象分别记录。

已确定最多四人、至少一人出征与队长展示规则；以下视角、移动、交互、编队与面板流程是本版细化建议，供后续实现采用。

| 区域／对象 | 展示与操作规则 | 状态 |
| --- | --- | --- |
| 酒馆视角 | 首版采用固定镜头的俯视 2D 单屏场景，主要交互点同屏可达 | 建议 |
| 队长 | 在可行走区域显示一名角色，代表整支队伍 | 已确定仅显示队长 |
| 其他已入队成员 | 不生成场景角色；头像、资料、装备预览仍可显示 | 已确定场景展示边界 |
| 招募点 | 招募公告板，打开招募面板 | 建议 |
| 整备点 | 整备桌，打开四人队伍与角色整备面板 | 建议 |
| 出征点 | 酒馆门口的远征地图，打开关卡选择与出征面板 | 建议 |
| 队长状态框 | 左上角显示队长头像、职业、队长标识和当前槽位 | 按用户要求采用魔兽世界式布局 |
| 队伍栏 | 队长框下方沿左侧排列其余已入队成员，最多三人；显示真实槽位编号与人数 N/4，不重复显示队长 | 按用户要求采用魔兽世界式布局 |
| 酒馆小地图 | 右上角圆形地图显示队长位置与三个交互点 | 布局已指定；地图功能为设计建议 |
| 常驻功能栏 | 底部中央用紧凑方格图标提供队伍、招募、装备、天赋和出征；图标显示快捷键，名称与说明悬停显示 | 按用户要求改为端游布局尺度 |
| 背包与菜单 | 右下角放背包、设置和指南；左下角放可收起的操作提示 | 建议 |

HUD 沿屏幕四周布置，中央保留连续的可行走视野，不遮住门口、交互落点和队长出生点。侧边状态框显示真实槽位编号，不能将队长框的位置误当成固定的 1 号槽位。宽屏增加的空间用于场景留白，窄窗口优先保持四个头像与文字可读；面板内容过多时滚动显示，不压缩为难以点击的小按钮。

角色与场景表现以用户提供的动物骑士图片为参考，使用粗深棕描边、圆润短身比例、简洁分层色块和红金强调色。HUD 采用更细的边框与半透明暗底，参考《魔兽世界》的玩家状态框、队伍框、小地图、底部动作栏与右下菜单分区，以鼠标和键盘的端游操作尺度设计。酒馆动作栏承载整备与出征功能，战斗技能仍在战斗场景处理。此处更新设计方向，不表示小地图或新 HUD 已接入原型。

端游布局建议以 1920×1080 为设计基准：队长框约 220×60，伙伴框约 165×34，小地图直径约 136，功能栏高约 50；上述为初始比例，正式实现还需结合可读字体与 UI 缩放校准。队长场景形象高度约为画面高度的 7%～9%，拉远镜头显示更多酒馆活动空间。移除顶部大型游戏标题、常驻大招牌、功能图标下的大字号标签和高亮外框；交互点保留小图标，悬停时显示名称。操作说明可收起，避免常驻覆盖场景。

“只显示队长”限定远征队伍成员，不限制店主等 NPC。招募候选角色首版使用面板卡片展示，避免将其他队员摆入酒馆场景。

### 1.2 队长移动

队长始终是酒馆中的移动对象，无需先点击选中。采用鼠标点击移动，一次点击产生一次命令；按住鼠标不持续产生新落点。

| 玩家操作 | 队长行为 | 反馈与边界 |
| --- | --- | --- |
| 左键点击可达地面 | 沿可行走路径移动，到达落点后停止 | 显示一个落点标记，抵达后消失 |
| 移动中左键点击另一处可达地面 | 取消原目的地与待交互对象，改走新路径 | 只保留最新落点 |
| 左键点击桌椅、墙壁等阻挡区域 | 不接受新命令，保留原合法命令 | 短暂显示“这里无法到达” |
| 点击可走但与当前位置不连通的区域 | 不移动到局部路径终点，不穿越阻挡 | 提示“无法到达该位置” |
| 右键点击场景 | 取消移动和待交互，在当前位置停止 | 清除落点和交互目标标记 |
| 点击队长自身 | 保持当前状态 | 不打开角色面板；资料从头像进入 |
| 打开功能面板或菜单 | 停止移动，取消待交互 | 关闭后保持站立，不续走 |

队长采用普通行走，不设置奔跑、体力、跳跃或翻滚。墙体、桌椅和柜台阻挡移动，路径沿家具外侧绕行；首版 NPC 不占据关键通道。行走速度和占地范围统一，不因切换职业产生穿门能力或移动效率差异。

路径在发出命令前检查完整可达性；途中路径失效时停止并提示，不无限原地行走。失去程序焦点时停止移动并取消待交互，返回程序后等待新输入。

### 1.3 场景交互

交互采用“点击对象 → 自动接近 → 到达后打开面板”。仅走进范围或从对象旁经过不会自动打开功能。

| 场景对象 | 点击后执行 | 打开的功能 | 特殊规则 |
| --- | --- | --- | --- |
| 招募公告板 | 前往公告板前的交互位置 | 招募面板 | 未招满时显示剩余空位；招满后仍可查看已招募状态 |
| 整备桌 | 前往桌前交互位置 | 队伍整备面板 | 默认查看队长；无成员时提供招募入口 |
| 远征地图 | 前往门旁交互位置 | 出征面板 | 接近酒馆门本身不切换战斗场景 |

鼠标悬停时，对象轮廓高亮，显示“招募伙伴”“整备队伍”或“准备出征”。已经位于对应交互范围内时，点击后立即开面板；超出范围则先移动。交互落点放在对象外的可行走区域，不将对象中心当作移动终点。

玩家同时只能有一个待交互对象。前往公告板途中点击整备桌，旧交互被替换；改点地面则只移动，到达后不会再弹出招募面板。连续点击同一对象只保留一次请求，到达后只打开一个面板。

若交互位置不可达，保留原合法命令并提示“无法靠近，请使用界面入口”。若对象在移动途中失效，则停止并清除待交互，不打开空面板。

常驻的队伍、招募和出征按钮可以直接打开相同面板，无需队长走过去；场景入口提供空间交互，界面入口方便反复整备。两种入口的权限、数据和出征校验一致。

### 1.4 面板与输入优先级

界面优先级为：场景加载遮罩 → 确认弹窗／菜单 → 当前功能面板 → 常驻队伍栏与按钮 → 场景对象 → 地面。一个点击只由最高优先级的有效对象处理。

| 当前状态 | 允许操作 | 场景处理 |
| --- | --- | --- |
| 自由行走或正在接近交互点 | 地面、对象、队伍栏与常驻入口 | 接收一个最新的合法命令 |
| 招募／整备／出征面板打开 | 操作当前面板；可点其他常驻功能入口切换面板 | 队长站立，禁止移动和场景交互 |
| 确认弹窗或菜单打开 | 仅操作最上层界面 | 队伍栏和其他入口不响应 |
| 保存队伍变更中 | 保留浏览，锁定变更按钮与确认出征 | 不接受重复提交 |
| 出征加载中 | 等待进度或失败提示 | 全部玩法输入锁定 |

功能面板同时只显示一个；从整备切到招募时替换面板，不逐层叠加。悬停提示不抢走面板焦点。点击面板外区域不会关闭面板，也不会移动队长。

Esc 一次只处理一层：关闭提示弹窗 → 关闭功能面板 → 无面板时打开菜单。关闭最上层弹窗后回到原面板及原查看对象，不同时关闭第二层。出征加载中 Esc 不取消已经开始的场景切换。

酒馆中的数字键 1～4 和 Q/W/E/R 不执行战斗选人或技能。右键停止只在场景操作可用时生效，不穿透面板。可点击按钮应有清楚的键盘焦点，Tab／Shift+Tab 移动焦点，Enter 激活；输入框获得焦点时不触发其他玩法动作。

### 1.5 四人队伍组建与顺序

队伍设四个槽位，容纳一至四名成员，包含一名队长；零成员时只能整备和招募，不能出征。空位显示“招募队员”，属于可选补充，不是出征条件。首版沿用战士、盗贼、法师、牧师四名固定候选，不新增随机英雄、替补库、解雇或职业重复选择。

**组队流程：**

1. 新档无成员时不显示队长，常驻队伍栏和招募入口可用；场景交互点点击后直接打开功能，暂不要求角色接近。
2. 招募卡显示职业、职责和技能摘要，点击“加入队伍”即招募，首版免费。
3. 新成员填入第一个空槽位，发放并穿戴八件初始装备，选择默认天赋。
4. 第一名入队成员自动成为队长，在酒馆默认落点出现；其余成员加入时只更新队伍栏。
5. 招募成功即保存。已招募卡显示“已加入”，连续点击不复制成员和装备。
6. 至少一人入队后即提供“检查整备”和“准备出征”入口，显示“当前 N/4 人，可出征”；招满时可显示“四人队伍已集结”，不自动出征，也不要求补齐空位。

队伍整备面板的四个槽位始终按战斗快捷键 1～4 从左到右排列。点击头像只改变查看对象；点击空槽位打开招募面板。

建议在整备面板提供“前移／后移”按钮，与相邻槽位交换，包含空槽位；边缘没有对应方向时禁用。调整后立即更新队伍栏并保存，队长身份跟随成员，正在查看的成员不变。出征面板提示“战斗快捷键按当前队伍顺序对应”，避免把数字键固定理解为某个职业。

### 1.6 切换队长

队长可以从任意已入队成员中指定，不要求队伍已经满员。仅在酒馆中操作，出征加载期间禁用。

1. 玩家点击任意已入队成员头像，打开或切换到该成员的整备页。
2. 当前队长显示“当前队长”；其他成员显示“设为队长”。
3. 点击“设为队长”后直接切换，不增加确认弹窗。切换可随时通过相同步骤恢复。
4. 取消原移动与待交互，在原位置、原朝向替换队长形象，镜头不跳转。
5. 队伍栏和角色资料同步更新队长标识，提示“已将 ×× 设为队长”，保存后显示成功状态。
6. 整备页继续显示该成员，不关闭面板，也不交换槽位。

切换队长不改装备、天赋和职业能力，不回复资源，不附加战力加成。不同形象使用同一行走占地；外观加载失败时沿用旧队长并提示，不留下两个角色或不可见的队长。

### 1.7 四人整备面板

整备桌和“队伍”入口默认查看队长；点击队伍栏头像则直接查看对应成员。面板上方是四人槽位，中间展示所选成员资料与八槽装备，侧边显示候选装备和属性比较，下方提供天赋选择及出征入口。

| 功能 | 玩家操作 | 生效与反馈 |
| --- | --- | --- |
| 查看成员 | 点击槽位头像 | 只切换资料、装备和天赋，场景仍显示队长 |
| 查看装备 | 点击武器、头盔、胸甲、肩膀、裤子、鞋子、戒指或护符 | 展示当前物品与该成员可穿戴的已拥有候选 |
| 比较候选 | 点击候选装备 | 预览换装前后属性及套装件数，尚不修改穿戴 |
| 更换装备 | 点击候选上的“装备”按钮 | 重新计算属性和套装效果，更新面板并保存 |
| 无替换件 | 查看只有初始装备的槽位 | 显示“暂无其他可用装备”，保留当前装备 |
| 选择天赋 | 点击另一个天赋选项 | 按现有二选一规则生效，展示收益、代价和最终技能参数并保存 |
| 已选天赋 | 再次点击当前天赋 | 不叠加、不重复提交 |
| 指定队长 | 点击“设为队长” | 按队长切换流程更新场景形象 |
| 调整顺序 | 点击前移／后移 | 交换槽位，成员的装备和天赋随成员保留 |

首版八槽保持完整，实际替换候选沿用现有肩膀与鞋子数据。面板不显示尚未接入的天赋树或装备强化入口。装备采用点击操作，不要求拖拽；跨职业、未拥有或部位不符的物品不得进入可装备候选。

已确认的装备、天赋、队长和槽位变更立即生效并保存，面板不设“全部应用”按钮。装备比较是预览，换槽位、换查看对象或关闭面板即清除预览；关闭面板不会撤销已成功保存的变更。

### 1.8 保存与异常反馈

队伍变更统一经过校验、应用和保存，同一次变更只提交一次。保存中锁定会改数据的按钮，仍可查看资料；成功后解锁并更新状态。

- 保存失败时恢复该次变更前的数据和展示，保留原装备、天赋、槽位及队长，提示“未保存，本次修改未生效”，提供重试入口。
- 招募与其初始装备作为同一次变更提交，不允许只保存英雄或重复发装。
- 关闭资料面板不清除已拥有物品，替换装备不销毁原装备。
- 存档中队长不存在时，回退到第一个有效成员；没有成员则显示空队伍并引导招募。
- 酒馆位置首版不写入长期存档，重启回到默认落点；队伍、槽位、队长、装备与天赋必须保留。

### 1.9 出征面板与前置检查

远征地图或常驻“出征”按钮打开同一面板。队伍至少一人且其他校验通过即可出征，一至三人的队伍无需补足成员；零成员时可以查看关卡，但不能开始出征。

面板分为关卡信息和队伍摘要：关卡显示名称、目标、敌人类型、机制提示及奖励；队伍摘要按四个槽位显示实际成员、队长标识、装备套装状态和当前天赋，每名成员提供“整备”入口。空槽位显示“空位”，不标红、不提示必须补人；出征校验仅检查实际成员的配置。

| 检查项 | 处理方式 |
| --- | --- |
| 队伍零人 | 禁用“确认出征”，显示“至少需要一名队员”，提供招募入口 |
| 队伍一至四人 | 人数校验通过；不要求补足空位，其他校验通过后允许出征 |
| 成员重复、无有效队长或配置损坏 | 尝试恢复有效队长；仍无法通过则禁用出征并提示修复队伍 |
| 装备或天赋配置不合法 | 阻止出征，标出对应成员并提供整备入口 |
| 没有替换装备或尚未成套 | 允许出征；初始装备是有效配置，套装不是门槛 |
| 存在上次待领取奖励 | 保留关卡浏览，禁用出征并提供“领取战利品”入口 |
| 未选择有效关卡或关卡未解锁 | 禁用出征并显示原因 |
| 保存中或已有出征请求 | 按钮显示处理中，拒绝重复请求 |

首版不新增体力、门票或金币出征费用。离开面板前已经确认的整备修改保留，查看关卡本身不消耗资源。

### 1.10 确认出征与返回整备

**正常流程：**

1. 选择关卡，查看实际出征成员配置、人数 N/4 和快捷键顺序。
2. 如需调整，点击某位成员的“整备”，打开对应资料；完成后通过“返回出征”回到原关卡并刷新摘要。此时 Esc 同样返回出征面板；直接从队伍栏打开的整备页则关闭回酒馆。
3. 点击“确认出征”作为最终确认，不再弹出第二个常规确认框。
4. 再次校验队伍与奖励状态，保存最新配置；保存失败时留在出征面板，不开始加载。
5. 保存成功后锁定本次一至四人的名单、槽位、队长、装备和天赋，显示“正在前往 ××”及加载进度。
6. 加载成功后按相同槽位仅生成实际出征成员，不自动补人或重排空槽位，默认选中队长；清除酒馆移动与交互输入，等待独立的开始战斗操作。

加载失败时返回酒馆，保留已经保存的队伍配置，重新打开原关卡的出征面板，提供“重试”和“返回酒馆”。失败请求不记为一次战斗、不生成战报、不发奖励；重复点击确认或重试也只能有一个有效加载请求。

关闭出征面板时队长保持原位置，不自动走出门。完成战斗返回后队长出现在酒馆固定返回点，头像顺序和队长身份保留；当前规则仍按下一次出征统一恢复生命与资源，无需新增收费治疗操作。

### 1.11 首次组队与重复出征示例

**首次出征：** 新档进入酒馆 → 点击招募入口 → 招募第一人并生成队长 → 检查装备和天赋 → 打开出征面板 → 选择关卡 → 确认出征 → 战斗场景仅该成员出现。玩家也可在出征前继续招募至二至四人，新增成员随队出场。

**重复挑战：** 战斗结束领奖 → 返回酒馆，仅显示队长 → 点击一位队员头像 → 比较并穿戴新装备 → 调整天赋 → 点击出征 → 检查实际成员摘要 → 再次进入战斗。

**改变途中目标：** 队长正在走向招募公告板 → 玩家点击整备桌 → 队长改道 → 到达后打开整备面板 → 原招募请求不会随后弹出。

**切换队长：** 场景显示战士 → 点击牧师头像查看资料 → 场景仍为战士 → 点击“设为队长” → 场景在原地改为牧师 → 槽位顺序与全队装备保持不变。

### 1.12 酒馆验收

- [ ] 队伍最多四人，非空时包含且仅包含一名队长；一至四人均可通过人数校验。
- [ ] 零成员时可以完成招募；第一人入队生成队长，其余成员只更新队伍栏。
- [ ] 重复招募不复制成员或初始装备，保存失败时不会留下半完成的招募。
- [ ] 酒馆只生成一名队伍角色，查看其他成员不更换场景形象。
- [ ] 点击地面绕过阻挡，到达后停止；无效落点不覆盖原合法命令。
- [ ] 场景右键可以停止移动并取消待交互，面板中的右键不会穿透。
- [ ] 经过交互范围不自动开面板；点击后在有效距离内才打开。
- [ ] 改点对象或地面会替换旧请求，连续点同一对象只打开一个面板。
- [ ] 不可达或失效交互有反馈，不无限行走；界面快捷入口仍可使用。
- [ ] 面板打开后队长停止，关闭后不续走；一次 Esc 只处理一层界面。
- [ ] 点击按钮和头像不误触地面，数字键和 Q/W/E/R 不执行战斗动作。
- [ ] 更换队长保留位置与朝向，不改槽位、不增加资源，不重复生成角色。
- [ ] 顺序调整后头像与战斗快捷键一致，队长身份及整备查看对象跟随成员。
- [ ] 装备比较不改穿戴，点击“装备”后属性、套装与保存一致。

- [ ] 零成员、配置非法或待领奖时不能出征，界面提供对应处理入口；一至三人不显示强制补人要求。
- [ ] 没有替换件或未成套不会阻止使用合法初始配置出征。
- [ ] 从出征进入某成员整备，再返回时保留原关卡并更新配置摘要。
- [ ] 确认出征不重复弹确认，保存失败不加载，加载中不接受重复请求。
- [ ] 加载失败可重试，不增加战斗次数、不发奖励、不丢已保存配置。
- [ ] 分别用一、二、三、四人出征，仅生成对应人数并默认选中队长；返回酒馆只显示队长。
- [ ] 重启保留队伍、槽位、队长和整备数据，位置回默认落点。

## 2 战斗场景操作

### 2.1 四人出场与操作对象

**已确定：本次出征的一至四名队员全部出现在战斗场景中，均可选择和操作；空槽位不生成角色。**

战斗中建议采用“单选角色、分别下令”：同一时刻只有一名当前操作角色，其他队员继续执行已有命令和自动行为。玩家可以随时切换实际出征成员；单人出征时始终操作该成员。

| 项目 | 规则 | 状态 |
| --- | --- | --- |
| 成员生成 | 使用酒馆确认的一至四名实际成员及其装备和天赋，保留槽位 | 已确定出场人数；配置继承沿用原型 |
| 初始选中 | 默认选中队长，并显示其技能与目标 | 建议 |
| 场景选人 | 左键点击己方角色进行选择 | 沿用既有操作 |
| 头像选人 | 左键点击对应头像进行选择 | 沿用既有操作 |
| 快捷键选人 | 1～4 对应四个队伍槽位 | 建议由原型的固定职业映射改为槽位映射 |
| 切换对象 | 只改变当前操作对象，不改变其他队员命令 | 沿用既有规则 |
| 队长身份 | 不随选人变化；队长与其他成员具有相同的可操作权限 | 建议 |

旧原型口径中 1～4 固定对应战士、盗贼、法师、牧师。接入可管理的队伍槽位后，应统一为槽位对应关系，头像顺序与快捷键始终一致。

空槽位没有可操作角色，按对应数字键不改变当前选中对象、不触发技能；战斗中仅显示实际成员的有效状态框。胜负检查针对本次实际出征成员：全部倒下即失败，不把空槽位计作阵亡或等待其生成。

### 2.2 战斗操作表

下表沿用现有键鼠战斗方案，作用对象始终是当前选中的角色。

| 玩家操作 | 执行结果 | 边界与反馈 |
| --- | --- | --- |
| 左键点击己方角色或头像 | 选中该角色 | 更新选中标记、资源、技能栏与目标信息 |
| 按 1～4 | 选中对应槽位的角色 | 不影响其他队员当前行为 |
| 左键点击地面 | 当前角色移动到指定位置 | 取消原追击／治疗跟随，抵达后保持位置 |
| 右键点击敌人 | 当前角色设置攻击目标 | 超距时接近至攻击范围，再执行自动攻击 |
| 牧师右键点击队友 | 指定持续治疗对象 | 超距时跟随至治疗范围 |
| 非治疗角色右键点击队友 | 不改变当前命令 | 不将队友作为攻击目标 |
| 按 Q/W/E/R 或点击技能按钮 | 使用当前角色对应主动技能 | 检查目标、距离、资源和冷却 |
| 按 P 或点击暂停按钮 | 暂停／继续战斗 | 暂停期间不执行新的移动、目标和施法命令 |
| 点击战斗速度按钮 | 切换 1×／2× 速度 | 当前速度持续可见 |

建议暂停时允许切换查看角色和技能说明；首版不缓存待执行的战术命令。右键空地不改变当前命令，左键己方角色只选人，不同时发出移动指令。

### 2.3 四人独立执行命令

每名角色分别保存移动、攻击或治疗目标，以及自己的生命、资源、公共施法间隔和技能冷却。当前选中角色变化，不重置这些状态。

例如，玩家先让战士攻击精英，再让盗贼攻击施法者，之后切换法师释放技能。战士与盗贼继续执行自己的目标命令。切换到牧师指定治疗战士后，其余三人的指令仍然保留。

手动移动优先于原来的追击或治疗跟随。移动到位后，角色按既有规则仅在有效范围内执行自动攻击或治疗，不立即自行跑回原目标身边。

### 2.4 技能与目标规则

沿用四职业各四个主动技能的结构。技能栏显示当前角色的技能名称、快捷键、消耗、冷却和目标类型。

- 敌方目标技能作用于当前合法敌人；治疗和保护技能作用于当前合法友方；自身技能不要求外部目标。
- 在目标无效、距离不足、资源不足、公共施法间隔或技能冷却未结束时拒绝施放，明确提示原因，不扣费、不启动冷却。
- 自动目标更新沿用既有战斗规则；更新后仍无合法目标时拒绝目标类技能。
- 按住技能键不连续重复施放；一次按下只产生一次施放请求。
- 查看、选择和技能施放分别处理。点击技能按钮不能同时触发地面移动。
- 每名角色独立计时，切换角色不能跳过原角色的冷却或公共施法间隔。

### 2.5 战斗界面与可读性

[战斗主场景 PC 布局概念稿](UI设计/战斗主场景-v01-PC布局.png)沿用酒馆新版的端游 HUD 尺度与角色画风。示例中战士为队长，盗贼为当前操作角色并以施法者为目标；底部显示盗贼的四技能和能量，上方目标框显示敌方生命与可打断施法。四名队员、两名近战敌人、一名施法者和一名精英同时出场，绿色友方血条与红色敌方血条辅以角色形象、队伍框和选中标识区分。地面条纹预警、治疗轨迹和战斗记录用于表现当前战术状态。图为视觉概念稿，截图中的数值和冷却是展示示例，不作为平衡配置。[内置图像工具生成记录与提示词](UI设计/战斗主场景-v01-PC布局-生成记录.json)随图保存。

**建议界面要求：**

| 界面元素 | 显示内容 |
| --- | --- |
| 四人队伍栏 | 按槽位显示头像、快捷键、生命、资源、倒下状态及队长标识 |
| 当前操作角色 | 场景选中圈和头像高亮同步，标识与队长标识有不同形状 |
| 当前目标 | 显示选中角色正在攻击或治疗的目标 |
| 技能栏 | 随选人即时切换，显示四技能的消耗、可用状态与冷却 |
| 敌人威胁 | 施法条、可打断提示和地面预警 |
| 操作结果 | 落点、攻击／治疗目标确认和技能失败原因 |

队长标识表示队伍身份，选中标识表示当前操作对象，两者可以出现在不同角色上。重要状态使用图形和文字辅助，不能仅用颜色区分。

### 2.6 倒下 暂停与场景退出

倒下角色退出本场行动，不接受移动、目标和技能指令，沿用当前无战内复活的规则。建议保留其头像并标明倒下，点击可查看信息；当前操作角色倒下后，自动选中槽位顺序中的第一名存活队员。队长倒下不改变其队长身份，也不单独触发失败；全队倒下或达到战斗时限才按战斗规则判负。

打开模态说明、设置或撤退确认时暂停战斗，场景不接收指令。关闭弹窗只恢复打开前正在运行的战斗；打开前已经暂停时仍保持暂停。程序失去焦点时暂停，返回后等待玩家主动继续。

胜利或失败后屏蔽战斗指令，进入结算。撤退需确认，取消时保留当前战斗状态；确认后按失败／撤退流程结算，不发胜利装备。

### 2.7 返回酒馆与状态衔接

**建议流程：**

1. 战斗结束后，记录结果、战报和待领奖状态。
2. 胜利奖励按现有流程领取并保存；同一场不能重复发放。
3. 返回酒馆，清理本次实际生成的战斗角色，只生成队长的酒馆角色。
4. 队伍成员、队长、装备、天赋和已领取奖励保持一致；战斗中的最后选中角色不覆盖队长。
5. 返回酒馆的指定落点，清除战斗目标、临时增益、移动指令和战斗选中状态。
6. 下一次出征按统一开场规则恢复生命和资源、初始化冷却，不继承上场战斗的临时状态。

队长在上一场倒下时，返回酒馆仍显示原队长形象。该显示属于酒馆状态，不构成战内复活。

### 2.8 Godot 接入要点

以下字段与动作是建议的职责划分，用于实现上述操作规则，不要求更换项目现有输入框架。

| 数据／动作 | 职责 |
| --- | --- |
| 队伍成员与四个槽位 | 保存成员身份和顺序，用于酒馆队伍栏及战斗生成 |
| 队长成员标识 | 单独保存队长身份，必须引用当前队伍成员 |
| 整备查看对象 | 只控制酒馆资料面板，不修改队长 |
| 战斗选中槽位 | 只控制当前战斗指令的接收者，不修改队长 |
| 酒馆移动与交互 | 仅在酒馆场景且界面未阻挡时生效 |
| 战斗选人 目标 移动与技能 | 仅在对应战斗状态且界面未阻挡时生效 |

输入先判断界面是否消费，再按当前场景转换为操作动作，最后校验角色与战斗状态。切换场景时清理未完成输入和待交互对象，避免出征按钮的点击被新场景当成移动或技能请求。

仓库内没有旧工程，客户端按 Godot 从零建，旧原型的战斗操作只作口径参考；工作包括战斗灰盒、酒馆场景、队长展示与切换、队伍槽位、相关存档及场景衔接。旧存档建议按当前原型职业顺序建立槽位，并将第一名有效成员设为默认队长；不得因此复制英雄或装备。

### 2.9 战斗与切场验收

- [ ] 实际出征的一至四名队员全部出场，每人可通过角色、头像和对应槽位快捷键选中。
- [ ] 实际成员均可分别移动、指定目标并使用自身四个技能，空槽位快捷键不改变当前选择。
- [ ] 切换选人不改变队长、不重置其他角色命令或冷却。
- [ ] 角色槽位、头像顺序与 1～4 快捷键对应一致。
- [ ] 队长标识与当前选中标识能分别辨认。
- [ ] 无效技能请求不扣费、不进入冷却，按住技能键不重复触发。
- [ ] 队长倒下后，其他队员仍可操作；仅队长倒下不直接判负。
- [ ] 暂停、模态弹窗和切场期间不会误发或积压战斗命令。
- [ ] 从酒馆出征后，由队长形象切换为本次实际人数的战斗角色；单人全倒即失败，空槽位不影响胜负检查。
- [ ] 战斗结束返回酒馆后，只显示队长，最后选中的其他队员不会替换队长。
