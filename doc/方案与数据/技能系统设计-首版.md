# 远征酒馆 技能系统设计：首版

版本：0.1｜日期：2026-11-14｜状态：开发规格，待实现与验收

## 1. 范围与交付

用 Godot 4.x / GDScript 在一张战斗验证场跑通五个瞬发主动技能：烈焰法师 Q/W/E/R、神圣牧师 Q。法师可单独进场，也可与牧师同时进场；牧师的 W/E/R 为空槽。验证场提供可选敌人、可受伤的友军和可控来伤，支持选人、右键指定目标、移动、技能按键与按钮、暂停和 1×／2×。

本稿细化开发计划 M3 的首批技能。技能基准取自[职业专精技能与天赋树设计](职业专精技能与天赋树设计.md)，战斗计算取自[战斗数值与属性系统设计](战斗数值与属性系统设计.md) 1.1，选人与目标命令沿用[游戏操作功能设计](游戏操作功能设计.md)。本稿确定这五个技能未细化的执行边界；其余 27 个主动技能、天赋和套装改写、专精切换界面、主动技能 AI、完整战报与战斗存档留到后续。

## 2. 技能配置

数值单位：距离为游戏世界米，时间为战斗秒，消耗为法力点，`P` 为施法者当次派生强度。所有技能瞬发，独立 CD 从施放提交计起，成功施放同时启动该角色的公共施法间隔（GCD）。

| 专精 / 槽位 | 稳定技能 ID | 名称 | 合法目标 | 法力 / CD | 有序效果列表 |
| --- | --- | --- | --- | --- | --- |
| `mage.fire` / Q | `mage.fire.flame_burst` | 烈焰爆破 | 当前存活敌人，≤8 米 | 25 / 8 秒 | 选中目标及距其中心 ≤2 米的敌人各受 1.70P 直接魔法伤害 |
| `mage.fire` / W | `mage.fire.fireball` | 火球 | 当前存活敌人，≤8 米 | 15 / 3 秒 | 主目标受 1.10P 直接魔法伤害；适用烈焰专精评级 |
| `mage.fire` / E | `mage.fire.flame_barrier` | 烈焰屏障 | 自身 | 20 / 16 秒 | 自身获得 1.50P 常规护盾，持续 6 秒 |
| `mage.fire` / R | `mage.fire.evocation` | 唤醒 | 自身 | 0 / 20 秒 | 自身立即恢复至多 35 法力 |
| `priest.holy` / Q | `priest.holy.greater_heal` | 强效治疗 | 当前存活友方，含自身，≤8 米 | 25 / 5 秒 | 主目标接受 2.40P 直接治疗；适用神圣专精评级 |

Q/W 的直接伤害及牧师 Q 的直接治疗享有稳定暴击收益。屏障和唤醒不享有暴击收益或专精评级；烈焰爆破不享有专精评级。按钮名称、说明和当前参数取自配置和派生值。

## 3. 数据与接口

静态配置用自定义 Godot `Resource`，每个技能一份 `.tres`，加载入表后按只读使用。用稳定 ID 关联，显示名称和槽位允许调整。临时对象用普通运行时数据；战斗结束全部销毁。

| 数据 | 字段与约束 | 谁负责 |
| --- | --- | --- |
| `SkillDef` | `skill_id, spec_id, name, icon, target_kind: ENEMY/ALLY/SELF, cast_range_m, mana_cost, cooldown_s, effects: Array[SkillEffectDef]`。SELF 的射程填 0。 | 技能目录 |
| `SkillEffectDef` | `kind: MAGIC_DAMAGE/HEAL/SHIELD/RESTORE_MANA, selector: PRIMARY/SELF/ENEMIES_AROUND_PRIMARY, power_coeff, flat_amount, radius_m, duration_s, uses_stable_crit, uses_mastery`。未使用的数值字段填 0。 | 技能目录 |
| `SpecLoadout` | `spec_id, slots[Q,W,E,R]`，每格为技能 ID 或空；技能归属必须匹配专精，同一组内 ID 不重复。 | 专精配置 |
| `ResolvedSkill` | `skill_id, target_kind, cast_range_m, mana_cost, cooldown_s, effects`。每个角色进战后从基础配置生成；首版直接取基础值。界面和规则共用这份参数。 | 派生模块 |
| `CombatantState` | `unit_id, team_id, position_m, hp, max_hp, alive, combat_stats, mana, max_mana, target_id, auto_mode, auto_progress, resolved_slots, gcd_ready_at, skill_ready_at[skill_id], shield`。死亡以统一生命状态为准；每人独立的资源与时钟。 | 战斗规则 |
| `ShieldState` | 可空；`shield_id, source_id, source_cast_id, remaining, expires_at`。同一角色一个常规盾池。 | 护盾结算 |
| `CastRequest` | `battle_id, request_seq, caster_id, slot, expected_skill_id`。按键或按钮触发时锁定角色和槽位，规则在执行时读取该角色当时的当前目标。 | 输入路由 |
| `CastResult` | `request_seq, caster_id, skill_id, accepted, reason, details, cast_id?`。成功分配战斗内唯一 `cast_id`（可取 `battle_id + request_seq`），失败无 `cast_id`；`details` 可带剩余秒数、所需法力或射程。 | 施法服务 |

单位 ID 在本场唯一且不复用；查不到 ID 与实体离场同样视为失效。位置从场景统一换算为世界米；HUD 和规则共用中心点距离。首版没有视线／遮挡判定。加载时校验 ID 唯一、槽位引用、必填字段、有限且非负的数值、合法效果与选择器组合、护盾时长和范围半径为正。配置或必要属性错误时阻止验证场启动，日志输出 ID 与错误字段；不要以零值替代缺项继续运行。

建议入口：`get_skill_view(caster_id, slot)` 只读，同步可用状态与技能栏；`try_cast(request)` 是主动技能唯一写入入口；`resolve_effect(context, effect, target_id)` 复用战斗伤害、治疗、盾与资源变更。场景负责输入与表现，规则模块持有唯一战斗状态。

### 3.1 实际配置示例

[技能数据示例](技能数据示例-v0.1.json)包含五份 `SkillDef`、两份 `SpecLoadout` 和一个独立的 Boss 扩展示例。JSON 用来展示字段和值；Godot 版本按上节映射成 `.tres`，首版不要求实现 JSON 加载器。`icon: null` 表示验证场使用占位图；`slots` 固定按 Q/W/E/R 排列，`null` 为空槽。

| 配置 | 关键字段 | 如何解释 |
| --- | --- | --- |
| 烈焰爆破 | `ENEMY → ENEMIES_AROUND_PRIMARY`；`power_coeff: 1.7, radius_m: 2` | 先选敌方主目标，再选其周边敌人；每人各吃一份完整的 1.70P 基础伤害。 |
| 火球 | `ENEMY → PRIMARY`；`power_coeff: 1.1, uses_mastery: true` | 只打主目标，1.10P 基础伤害享受烈焰专精评级。 |
| 烈焰屏障 | `SELF → SELF`；`power_coeff: 1.5, duration_s: 6` | 生成自身护盾；6 秒是盾的持续时间。 |
| 唤醒 | `SELF → SELF`；`power_coeff: 0, flat_amount: 35` | 固定恢复 35 法力，实得量受法力上限限制。 |
| 强效治疗 | `ALLY → PRIMARY`；`power_coeff: 2.4, uses_mastery: true` | 治疗当前友方，含自身；2.40P 基础治疗享受神圣专精评级。 |

例如牧师按 Q 时，输入层生成如下请求。此时 `target_id` 留在角色战斗状态中，由施法服务在执行请求时读取。

```json
{
  "battle_id": "test_battle_01",
  "request_seq": 12,
  "caster_id": "hero_priest_01",
  "slot": "Q",
  "expected_skill_id": "priest.holy.greater_heal"
}
```

**Boss 扩展示例：分摊陨石。** 示例文件的 `enemy_ability_examples` 对应[敌人与 Boss 系统的 EnemyAbility](敌人与Boss系统设计.md)，不进入玩家专精槽位或首版技能目录。它在前摇开始锁定地面点，2 秒后用落地时的位置选出半径 2.5 米内存活的敌方英雄。`ENEMIES_IN_LOCKED_AREA` 是新增选择器；`damage_distribution: SPLIT_EVENLY` 表示把效果的 3.0P 基础量除以名单人数，再走各目标自己的防御结算。圈内无人则落空。未配置分摊字段的已有范围技能仍按每目标完整伤害结算。

## 4. 时间、输入与目标

- **战斗时钟。** 使用固定战斗步长推进模拟（首版建议 1/60 秒）。1× 每真实秒推进 1 战斗秒；2× 执行更多相同长度的模拟步。自然回蓝、盾过期、普攻和技能都使用战斗时间。每个执行时间点先结算到期、周期和自然恢复，再按接收序号执行玩家命令；同刻后续命令看见前一命令的写入。独立 CD、GCD 以 `ready_at` 表示，`now >= ready_at` 即可用；到期落在两步之间时，首个不早于到期的执行点可用。浮点边界统一在时钟层处理，不由 HUD 的显示值决定。
- **生命周期。** 开战法力 100／100，GCD、独立 CD 均可用，初始无盾，普攻进度 0。切人不影响任何角色的状态。暂停时战斗时钟冻结，可看技能说明和切换查看对象；移动、设目标和施法输入不缓存，暂停前尚未执行的战术命令丢弃。战斗结束和切场清空待处理命令；旧战斗的请求不得落到新战斗。
- **输入。** 按键非重复按下或点击按钮各自产生一次请求。按钮点击由 UI 消费，不向场景透传成地面移动。按下角色切换键后，后续技能输入绑定新角色；已生成的请求保留原施法者。选中单位的当前目标由交战命令和既有自动重选规则维护，不取鼠标指向。
- **目标。** 敌方技能只读当前敌方目标，友方技能只读当前友方目标；自身技能忽略外部目标。牧师右键队友或自己可设置友方目标；左键只选人。沿用既有自动重选结果，施法服务自身不重选、不代选最低血量、不追近，也不改写普攻目标、模式或进度。牧师对敌攻击时按 Q 提示需要友方；右键重新指定友方后才能施放。满血的当前友方仍是合法目标。
- **几何。** 主目标以施法者到目标中心的距离判定，8 米边界包含。烈焰爆破以主目标施放时的位置为圆心，主目标先结算，其余存活且可被选中的敌人按稳定单位 ID 排序并去重。边界 2 米包含；副目标无需另外满足施法者 8 米射程。友军、倒下单位及不可选中的敌人不进快照。

## 5. 施法事务与错误反馈

每条请求同步处理「准备 → 提交 → 结算」，流程中不等待动画、计时器或界面回调。准备阶段可构造临时数据，但不写战斗状态。多个条件同时失败时，按下表行序返回第一个原因；只读技能检查与实际施法使用相同判定。

| 顺序 | 判定 | 失败码与玩家提示 |
| --- | --- | --- |
| 1 | 本场请求且处于战斗进行中，输入未锁定 | `STALE_BATTLE` 忽略并记调试日志；`BATTLE_PAUSED`「战斗已暂停」；`INPUT_LOCKED`「当前无法施放」 |
| 2 | 角色存在、可操控且存活 | `NO_CASTER`「没有可操作角色」；`CASTER_DOWN`「角色已倒下」 |
| 3 | 槽位有技能且仍与请求和当前专精匹配 | `EMPTY_SLOT`「该槽位没有技能」；`SKILL_CHANGED`「技能已更新，请重新施放」 |
| 4 | 目标存在、可选、存活且阵营一致；验证距离并准备效果目标快照 | `INVALID_TARGET`「需要有效的敌方／友方目标」；`OUT_OF_RANGE`「目标超出射程」 |
| 5 | 当前法力 ≥ 本次消耗 | `NOT_ENOUGH_MANA`「法力不足（需要 {cost}）」 |
| 6 | GCD 已结束 | `GCD_ACTIVE`「公共冷却中」 |
| 7 | 技能独立 CD 已结束 | `SKILL_COOLDOWN`「技能冷却中（剩余 {seconds} 秒）」 |

通过校验后，锁定本次派生参数、施法者输出属性、战斗时间和效果目标列表。一次性扣法力并写入 `gcd_ready_at = now + gcd_s`、`skill_ready_at[skill_id] = now + cooldown_s`。再按效果表及目标顺序同步执行，记录每个效果的实际结果；整次施放结束后才向 HUD、表现、战报和胜负判定发布结果。击杀或脱战事件不能在范围结算中途切场。

失败请求不扣费、不改时钟、不写目标或普攻状态、不发成功施放或命中事件，也不延后自动补发。两条不同请求同刻执行时，第一条若成功，第二条看到新的法力和 GCD；重复投递同一请求序号直接丢弃。技能配置和效果输入在提交前验证完整；预期的零收益效果是成功结算，不能以失败或自动退款处理。程序错误记详细日志并停止当前验证场，避免继续用半结算状态。

## 6. 五技能的结算与事件

### 6.1 法力和时钟

```text
h = 0.30 × 急速评级 / (急速评级 + 1000)
gcd_s = max(0.75, 1 / (1 + h))
法师每秒回蓝 = (3 + 0.035 × 精神) × (1 + 0.50h)
牧师每秒回蓝 = (3 + 0.035 × min(精神,150) + 0.003 × max(精神−150,0)) × (1 + 0.50h)
自然恢复后法力 = min(100, 当前法力 + 每秒回蓝 × 战斗时间增量)
```

急速不改变独立 CD 和护盾时长。唤醒的实得量为 `min(35, max_mana − 当前法力)`，不乘急速恢复因子，满蓝仍成功并启动 GCD、CD。记录实际恢复量，溢出不转为其他收益。生命、法力和结算量用浮点数，取整只用于显示；法力不足与否用实际值判断。

### 6.2 伤害、治疗与护盾

- **烈焰爆破、火球：** 走 1.1 的直接魔法伤害管线：先算 `kP × 同组输出倍率 × (1+m) × 命中质量q × 稳定暴击C`，再按穿透后的魔抗与目标减伤缩放，依次扣护盾、扣生命，记录吸收、有效生命伤害和过量。每个敌人使用自己的回避、魔抗、减伤和盾。烈焰爆破的 `m=0`，火球按烈焰专精系数 0.45 换算。没有随机未命中或暴击事件。
- **强效治疗：** 原始治疗为 `2.40P × 同组治疗倍率 × (1+m) × C`，神圣专精系数 0.45。补血取原始治疗与当前缺血量中的较小值，其余为过量。满血时施放成功、有效治疗为 0；倒下目标在校验时拒绝。有效治疗才进入治疗贡献与仇恨。
- **烈焰屏障：** 生成时锁定 `1.50P × 同组盾量倍率`，到期时间为施放时刻 +6 秒。新盾严格大于当前剩余值才替换；相等或较低时保留旧盾与其到期时间，技能仍成功扣费并进入冷却。盾在目标减伤后吸收，在耗尽、到期或角色死亡时移除；到期与同刻来伤相比优先移除。替换和到期都不计吸收。

公式细项以[战斗数值设计第 4–8 节](战斗数值与属性系统设计.md)为准。仇恨使用第 10 节接口：普通专精伤害按有效生命伤害，治疗按有效治疗的 20% 在符合条件的敌人间均分；盾生成、吸收、过量治疗和回蓝不产仇恨。

成功施放输出一个结果及有序效果明细，明细至少包含 `cast_id, skill_id, source_id, target_id, effect_kind` 和实际量。伤害区分吸收、有效生命伤害和过量；治疗区分有效、过量；护盾区分建立／替换／保留，吸收事件按 `shield_id` 回溯来源；回蓝记录实得。HUD 根据当前角色切换名称、槽位、消耗、目标类型与独立冷却倒计时，另显示 GCD；失败短提示可合并相同原因，避免长按或点按刷屏。动画和飘字消费结算结果，不能驱动或重复结算。

## 7. 开发顺序与验收

1. 建立技能目录和加载校验，加载两份专精槽位表，完成准备／提交接口及独立时钟。
2. 先接火球和强效治疗跑通敌／友方单体，再接烈焰爆破的范围、屏障的生命周期和唤醒的资源上限。
3. 接入验证场的输入、技能栏和事件日志。规则用固定数据验证；在 Godot 验证场人工检查选人、右键、按钮、暂停和离场交互。

**数值夹具：** 施法者 `P=100`，评级全为 0、无增减益；目标回避、魔抗、减伤、护盾默认 0，未声明时血量足够。此时直接伤害与治疗 `C=1.025`、`q=1`、`m=0`，GCD=1 秒。下表每行独立初始化；法力及伤害采用结算前后同刻快照（排除自然恢复，或按公式单列）；浮点结果误差 ≤0.001。

| 编号 | 操作／条件 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 烈焰爆破：主目标距法师 8 米，两名次目标分别距主目标 2 米、2.01 米；另放友军和倒下敌人 | 仅主目标和 2 米次目标各受 174.25 伤害、各一次，即使该次目标离法师超过 8 米；消耗 25、独立 CD 8 秒、GCD 1 秒。 |
| A02 | 火球：目标魔抗为 1000、其他条件不变；用另外一次独立试验将法师专精评级设为 1000 | 无专精评级时伤害 56.375；专精评级 1000 时伤害 69.059375。消耗 15、独立 CD 3 秒。 |
| A03 | 烈焰屏障：无外部目标；施放后承受一记结算后 180 的伤害 | 消耗 20、独立 CD 16 秒；新盾 150、到期 +6 秒。到期前受击吸收 150、掉血 30；单独重跑，在恰到期时受击则吸收 0、掉血 180。 |
