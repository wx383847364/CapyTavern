# 项目总览

这份文档是 CapyTavern 长期主文档体系的第一入口。

## 项目定位

- 项目名称：CapyTavern
- 玩法定位：远征酒馆。酒馆整备队伍，再进一场实时指挥战斗。草案见 `doc/方案与数据/`
- 美术方向：2D，角色使用 Spine
- 客户端：Godot 4.7.2.stable
- 服务端：暂无，先本地 Mock
- 仓库：单仓，`/Users/bruce/work/CapyTavern`

## 当前阶段

- 当前阶段：P0–P4 灰盒闭环已落地，战斗 AI 与目标 HUD 已进入 v0.1.0 试玩版
- 当前主线：补当前版本独立导出包从空档到自然胜利、领奖和读档的实时全流程证据
- 当前建议起点：阅读最新迭代记录及开发计划的首批正式五技能验收节

## 当前稳定结论

- git 单仓；各路径唯一写者见 [目录与写权边界](架构与边界/目录与写权边界.md)。
- 客户端引擎定为 Godot 4.7.2.stable，2D Spine。存档用 `ownedItems` 记已拥有物品。`.godot/` 不进 git。
- 首版无热更新。分层见 [分层与热更边界](架构与边界/分层与热更边界.md)。
- 任何人不自行 commit，只 prepare；human 明确说「提交」才 commit。
- 提交标题固定为 `[TMMSSSSS] 类型：摘要`，细则见 [Git 提交与确认规则](协作与执行/Git%20提交与确认规则.md)。
- `locks.md`、`dispatch.md` 是运行态，不进 git。
- 构建产物仅跟踪 `build/debug/`，其中 Mac 可执行文件使用 Git LFS。其他构建产物留在本地。
- `tools/doc_maintenance/**`、`tools/repo_maintenance/**`、`.githooks/**` 归制作人；整棵 `tools/**` 不预支给单一岗位。
- 表现岗定名为「酒馆表现」，评审并入制作人。

## 试玩导出

- 从仓库根目录运行 `python3 tools/client/build_debug.py`，用同一份 Godot 工程快照导出 `build/debug/CapyTavern.app` 和 `build/debug/web/index.html`。两项导出都成功后覆盖上一批，Godot 使用 Release 模板。
- 运行 `python3 tools/client/build_debug.py --serve`，在浏览器打开 `http://127.0.0.1:8765/web/`。Web 字体随包导出，授权文件在 `build/debug/web/NotoSansSC-OFL.txt`。

- 将 `build/debug/web/` 的新版推到 `main` 后，GitHub Actions 自动更新 [公开试玩链接](https://wx383847364.github.io/CapyTavern/)。
