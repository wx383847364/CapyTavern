# 目录与写权边界

本页把 `TEAM.md` §2 的路径所有权落到目录上，供开工前核对。两处冲突时，以 `TEAM.md` 为准，先改 `TEAM.md` 再同步本页。

## 仓库根目录

| 路径 | 内容 | 唯一写者 |
|---|---|---|
| `client/` | 客户端工程、脚本、场景、存档 | 酒馆程序 |
| `client/assets/art/**` | 2D 美术资源、Spine 素材 | 酒馆表现 |
| `client/assets/ui/**` | UI 素材、Prefab / 场景表现 | 酒馆表现 |
| `export/**` | 导出物、构建产物 | 酒馆表现 |
| `design/**` | 玩法、数值、文案、配表 | 酒馆策划 |
| `server/**` | Mock 服务端、本地联调 | 酒馆服务器 |
| `protocol/**` | 协议、数据契约 | 酒馆服务器 |
| `doc/**` | 长期文档、方案、迭代记录、裁决 | 酒馆制作人 |
| `locks.md` | 写锁台账 | 酒馆大肥鱼（调度台） |
| `dispatch.md` | 派发、交接、阻塞台账 | 酒馆大肥鱼（调度台） |
| `tools/doc_maintenance/**` | 提交取号、提交信息校验 | 酒馆制作人 |
| `tools/repo_maintenance/**` | hook 安装 | 酒馆制作人 |
| `tools/project_dashboard/**` | 本机进度控制台（代码）；登记表在 `doc/方案与数据/控制台登记.json` | 酒馆程序 |
| `.githooks/**` | commit-msg、pre-commit | 酒馆制作人 |
| `TEAM.md` | 团队规则 | 制作人 |

说明：

- `client/`、`design/`、`server/`、`protocol/`、`doc/` 动手前先看 `locks.md`；同一目录同一时刻只允许一个写者。
- `doc/**` 归制作人。调度台只在 human 直接指派时代写，写完交回制作人确认。本轮文档系统由调度台代写，制作人已于 2026-11-04 确认收回。
- `tools/**` 不整树交给某一岗。上表 `doc_maintenance`、`repo_maintenance` 归制作人，`project_dashboard` 归程序。以后客户端构建或资源管线放 `tools/client/**`，归酒馆程序，先改 `TEAM.md` §2 再使用。
- `export/**` 的写者是酒馆表现；产物留在本地，不进 git。

## 不进 git

| 路径 / 模式 | 原因 |
|---|---|
| `locks.md`、`dispatch.md` | 运行态台账 |
| `.godot/` | Godot 生成目录 |
| `Library/`、`Temp/`、`obj/`、`Logs/` | Unity 生成目录（引擎未定也先拦） |
| `*.csproj`、`*.sln` | 引擎生成的工程文件 |
| `export/`、`build/` | 导出物、构建产物 |
| `.DS_Store` | macOS 元数据 |

## 引擎

human 2026-11-04 定为 Godot 4，角色用 2D Spine。小版本已锁定为 4.7.2.stable。

- 三刀、领奖、`ownedItems` 和两份稿的引擎抬头都已定。程序做 P0 时创建 `client/`，并把 Godot 小版本写回程序计划。
- 不提交 `.godot/` 和导出物。`.gitignore` 继续拦住 Godot 与 Unity 的生成目录。
- 分层和热更见 [分层与热更边界](分层与热更边界.md)。首版无热更新、无真服务端。
