### 2026-11-27 移动显示修复

同一台 Apple M4 Max、1280×720 画面，以固定种子 271126 在四人混编出征中执行同一组三次往返指令。从带测量代码的 Mac 和 Web 导出包逐帧记录角色实际绘制坐标与绘制结束时间。Mac 使用 60 Hz 显示器。Chrome 使用无头模式，经硬件加速的 ANGLE Metal / WebGL 2 渲染。下表各项按修复前 → 修复后排列，长帧指相邻绘制间隔大于 25 毫秒。

| 平台 | 移动中显示位置更新间隔中位数 | 持续移动区间内位置有变化的帧 | 整帧间隔 p95 / p99（毫秒） | 长帧占比 |
| --- | --- | --- | --- | --- |
| Mac App | 50.01 → 16.67 毫秒 | 120/365 → 365/365 | 16.79 / 17.27 → 17.05 / 17.23 | 1/448 → 1/448（均为 0.22%） |
| Chrome | 50.0 → 16.7 毫秒 | 120/366 → 366/366 | 18.8 / 20.3 → 19.0 / 20.2 | 0/449 → 0/449 |

- 两端稳定移动区间内，45–55 毫秒的位置更新间隔分别由 116 次和 117 次降到 0 次。Mac 新旧两版都限制到 60 FPS，旧版前台占比 40%，新版 100%；测量脚本统一屏蔽外部输入和失焦暂停。整帧耗时包含宿主调度，这组数据用于区分角色跳步与长帧。
- 法师＋牧师正式出征复测中，两端的位置更新间隔也由 50.0 降到 16.7 毫秒。修复后 Mac 整帧 p95 / p99 为 17.65 / 18.41 毫秒，长帧占 0.46%，包含一次失焦期间的 1.016 秒间隔。Chrome 为 17.8 / 19.3 毫秒，长帧为 0。
- 以 60 和 120 FPS 的固定渲染步分别验证绕障转角、玩家与无人操作 AI、多人交叉走位、头顶命中和闪现。合成远端通过同一战斗 View 验证，覆盖 100 毫秒缓冲与 250 毫秒断流阈值下的乱序、重复包、短缺追时、传送丢首包及重连。120 FPS 为程序驱动，真实网络与输入到屏幕端到端延迟尚未测量。
- 同一输入下，战斗种子 77 的 10,216 条单位坐标与 751 条事件逐条一致；酒馆三个交互点的 225 条位置和面板状态、238 条事件亦一致。酒馆自检 86 项、战斗回归 3,152 项、出征窗口走查 391 项通过。
- 完整方案见[《移动显示修复方案 v0.1》](../方案与数据/移动显示修复方案%20v0.1.md)。稳定规则见[《游戏操作功能设计》](../方案与数据/游戏操作功能设计.md)。原始帧与硬件信息保存在本机 `/private/tmp/capytavern-motion-ab.lFlsUfHq`，回归日志与前后轨迹保存在 `/private/tmp/capytavern-s1a-qa-motion.mr5Qlp2f`。
